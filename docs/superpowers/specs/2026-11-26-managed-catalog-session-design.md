# NovaHub 后台源库、登录保持与历史管理设计

状态：用户已于2026-11-26授权直接实施，并强调同时解决更新后登录丢失。设计审阅通过；实现和部署状态另行记录。

## 已确认需求与约束

- 源可在后台自动获取更新，用户前端不展示源名称、地址和源管理入口。
- 搜索避免过量并发，优先选择实际质量最好的可用结果。
- 广告位为后期预留，暂不展示；今后从管理后台配置启用。
- 直接覆盖安装新版 APK 后应保持有效登录。用户确认最近一次覆盖升级也需要重新登录。
- 历史观看记录可删除。
- 普通用户与会员有实际权益差异，不增加付费 API 成本；保留普通用户已拥有的播放、阅读、系统听书和基础云同步。
- 沿用 Pages 前端、Python 标准库后端、SQLite、Android WebView，以及 GitHub 构建 APK 的方式。
- 源库、历史迁移不得损坏已有收藏、书架或观看进度；数据库和密钥不得随源码部署被替换。

## 方案取舍

1. 小步修改：保留客户端逐源搜索，仅隐藏源入口并补源订阅。工作较小，但所有设备重复访问上游，难以统一质量选择与并发控制。
2. 后台统管（建议）：后台维护持久化源库，统一检索、去重、选线和故障反馈；客户端展示内容与播放状态。需同时改后端和前端，但可完整覆盖本次诉求。

用户已同意按后台统管方案实施。以下默认参数由实施者提出，可在后台调整。

## 一、后台源库与更新

- `sources.json` 作为首次安装的种子，运行状态保存在 SQLite，发布新版不会覆盖运行中的源库。
- 管理后台可管理可信订阅地址、候选源、启停、最近检查、失败原因与上一版配置。
- 接受纯 JSON 形式的普通源数组、LibreTV SourceList、TVBox 中可直接访问的 MacCMS JSON API；不执行订阅中的脚本或二进制。
- 新源按规范化 API URL 去重；保留现有种子的稳定 ID，以便兼容旧收藏和历史。停用时保留 ID 映射。
- 旧客户端自定义源以登录用户为边界迁入私有兼容表，保留 `(user_id, legacy_src_id)` 到规范化来源的别名；不自动加入全站共享源库。迁移只接受有身份的本人快照，仍经过公网目标验证与数量限制。
- 旧自定义源只用于解析该用户已有收藏、历史和进度。未登录时保留本机旧信息，登录后迁移；源无效时保留记录并显示暂不可用，不自动跳到同数字 ID 的其他影片。同一旧 ID 对应不同地址时保留冲突记录，不静默覆盖。
- 管理员可在单独检查后将私有来源提升为共享候选。前端不再暴露源管理入口，不妨碍后台保留和解析迁移别名；原始私有 API 地址不进入公众响应或日志。
- 每日检查订阅变化，每6小时检查启用源。使用条件请求和失败退避。后台可手动触发同一任务，任务去重，避免重复执行。
- 下载订阅最多2MB、最多100条候选；每轮新增候选最多20条，滚动检查。沿用 `safe_http` 的公网目标、重定向、超时与响应体限制。
- 候选需要通过接口结构、非空目录、详情与有限体积的媒体抽检后自动启用；默认两轮检查通过，间隔至少30分钟。
- 连续3轮失败暂停参与检索，冷却后复检；允许管理员手动停用并保持停用，不被订阅重新打开。
- 更新失败保留上一版源库及其时间，不能把一次失败覆盖为空列表。后台支持配置回滚。
- 首发必须核验至少一份实际可更新的外部订阅；不能只轮询本项目固定种子文件并声称实现自动发现。具体公开订阅由实施者调研验证，不要求用户寻找。
- 本轮先实现影视；音乐与小说沿用现有独立适配器。

## 二、统一检索和质量选择

- 客户端改为请求后台聚合搜索，不直接向全部影视源并发请求，也不使用公共 CORS 代理作为影视搜索后备。
- 默认每个查询最多3个在途上游请求；后台全部影视搜索/探测共享最多6个在途上游请求。前台查询优先于定时探测。
- 查询先覆盖健康度最高的源，再在结果不足时扩展，单个查询最多8个源，整体截止时间8秒。每源超时4秒，单页，结果和响应体受限。
- 相同查询短期缓存120秒；相同的在途查询合并。新关键词取消旧请求展示，迟到结果不得覆盖新结果。过载返回可重试提示而非无界排队。
- 同片按标准化标题、年份、类型、季数与语言版本保守合并；年份、季数、剪辑版不同或信息不足的结果不强行合并。
- 来源质量参考最近成功率、实际播放反馈、延迟、集数完整度和经过验证的媒体信息。标题中的“4K/高清”等字样不作为已验证清晰度。
- 详情优先选与用户需要的影片版本和集数匹配、可播放的线路，再在其中选质量较好的线路。可靠性优先于未经验证的高分辨率。
- 播放失败自动尝试最多2条同版本同集备用线路，保留可映射的集数和进度；无法确定同集时提示用户选择，不能跳到另一部影片或另一集。
- 公众接口不返回上游 API 地址；源地址和健康诊断仅管理员可查看。这是产品界面与接口边界调整，不承诺播放媒体 URL 无法被客户端观察。

## 三、登录保持：先定位，再修复

现状：入口固定，WebView DOM Storage 已启用；v2.4.3 到 v2.4.4 未修改 `db.py`，没有发现主动清理网页存储的安装逻辑。现有 Token 期限30天，没有活跃会话续期。`/api/auth/me` 对无效 Token 返回200和空用户，客户端立即清除本地会话。覆盖升级丢登录尚未复现，不能认定根因已找到。

- 首先区分 Token 丢失、过期、密钥改变、凭据撤销或请求发往错误后端；诊断只记录状态类别、版本和时间，不记录 Token、密码或完整凭据。
- 使用同一个持久化数据库验证后端重启/代码升级前后有效 Token 不失效；入口、包名、签名保持稳定。
- 以复现结果选择最小修复。若为网页存储丢失，增加仅受信任主文档可调用的原生会话持久化；凭据存储应受 Android Keystore 保护、排除云备份，且显式退出后不能恢复旧会话。不得给任意 iframe 暴露读取凭据的桥接口。
- 若为自然过期，增加受服务器校验的活跃会话续期；密码变更/撤销仍立即使旧会话失效，不能改成无限有效 Token 或只靠缓存用户信息绕过登录。
- 网络超时、隧道重连和非鉴权错误不得清空本地有效会话；无效凭据使用明确的鉴权响应，并避免并行旧请求清除新登录。
- 验收包含冷启动、进程被杀、同签名覆盖升级、后端重启、短暂离线、主动退出、改密码和会话过期。
- 若只有用户设备可复现，先提供脱敏诊断和明确测试步骤；未做真实覆盖升级验证时必须如实标为未验证。

## 四、历史记录与同步

- 首页“继续观看”提供管理入口；历史管理支持删除单条和二次确认后全部清空，手机和平板均可操作。
- 删除仅移除观看记录和对应续播位置，不删除收藏、片单或书架。正在播放的条目删除后，本次播放停止写回历史，重新主动打开后才能再次记录。
- 修复多源数字影片 ID 冲突，至少用来源 ID 与影片 ID 组成稳定键；聚合后继续维护旧键映射。
- 删除操作必须进入云同步；记录删除版本/时间或墓碑，使另一台设备的旧快照不能复活已删除记录。登录恢复和离线后重连也必须遵守删除记录。
- 全站源库不再进入用户同步快照；兼容读取旧快照，但忽略其中的公共源表与会员/权限字段。
- 旧快照中的 `source` 仅在首次兼容迁移时作为用户私有来源导入，不作为公共源表覆盖输入；同步完成前不得删除本机旧别名所依赖的数据。

## 五、广告预留与会员权益

- 广告/赞助位置保留配置与渲染能力，当前无配置时不占空白位置、不展示示例内容。
- 管理后台能配置启用、投放位置、标题/描述、图片URL、按钮和HTTPS跳转地址，并预览；不开放任意第三方脚本注入。
- 为未来广告服务预留供应商标识和适配接口；本轮不集成广告联盟 SDK。将来具体供应商接入需实现其对应适配器，不能仅填写任意脚本就获得系统权限。
- 全局开关关闭时全部用户均不展示。启用后普通用户展示站内配置的广告，Pro免展示；不承诺去除上游视频或音乐自带广告。
- 本次升级将历史示例赞助位迁为未启用，保留已有配置值；后续由管理员明确开启。
- 保留普通用户基础同步；高音质入口按现有服务端会员校验，实际音质不足时明确回退，不用标签假装无损。
- 会员中心展示真实的剩余天数与已启用权益，删除没有实际能力支撑的“极速源”等文案。本轮不加入付费听书，也不顺带扩展历史版本备份或追更提醒。

## 六、实施与验证边界

- 分成独立可验收的改动：登录定位与修复、源库与聚合检索、前端历史与同步、广告与会员显示。全套验收后统一发布。
- 为会话撤销、更新后会话保持、全局并发限制、失效源隔离、配置回滚、删除防复活编写行为测试；保持既有Python/前端/导航/听书检查通过。
- 同步根目录与 `docs/` 的前端文件，保留当前未提交的 `.gitignore` 改动；新版本通过 GitHub 构建签名 APK。
- 部署前保存数据库与代码备份，迁移可重复执行，部署后核对版本/哈希、任务状态及实际播放。源订阅与现有用户数据不写入公开配置或日志。
- 本文是已确认的设计；功能实现、登录修复和真实升级验证均须分别给出证据，不能用设计完成代替实现完成。
